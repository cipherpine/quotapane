## The audit delta (measured — corrected)

Method: `cargo generate-lockfile` on the real workspace with `tray-icon` added
(gated to Windows/macOS), then `cargo tree` per target + `cargo-deny 0.20.2`
against the real `deny.toml`. Adding `tray-icon` puts **nine** entries in
`Cargo.lock`:

### Five SHIPPED crates (compile on Windows and/or macOS)

| Crate | Version | License | Notes |
|---|---|---|---|
| `tray-icon` | 0.24.1 | MIT OR Apache-2.0 | The API. tauri-apps org. |
| `muda` | 0.19.3 | Apache-2.0 OR MIT | Menu library; non-optional dep of tray-icon; same org. |
| `crossbeam-channel` | 0.5.16 | MIT OR Apache-2.0 | Event channel. Past the RUSTSEC-2025-0024 fix (0.5.15). |
| `crossbeam-utils` | 0.8.22 | MIT OR Apache-2.0 | Transitive of the above. |
| `keyboard-types` | 0.7.0 | MIT OR Apache-2.0 | Menu accelerator types. No I/O. |

### Four PHANTOM crates (in the lockfile, compiled on NO supported target)

| Crate | Version | License | Notes |
|---|---|---|---|
| `dirs` | 6.0.0 | MIT OR Apache-2.0 | tray-icon depends on it ONLY under `cfg(any(target_os="linux","dragonfly","freebsd","netbsd","openbsd"))`. |
| `dirs-sys` | 0.5.0 | MIT OR Apache-2.0 | transitive of `dirs`. |
| `redox_users` | 0.5.2 | MIT | transitive of `dirs-sys` (Redox path). No advisory. |
| **`option-ext`** | **0.2.0** | **MPL-2.0** | transitive of `dirs-sys`. The one non-permissive license in the whole tree. |

**Why "phantom".** `tray-icon` declares `dirs` only under its Linux/BSD cfg, and
we gate `tray-icon` to `cfg(any(target_os="windows", target_os="macos"))`. The
intersection is empty, so the chain `tray-icon → dirs → dirs-sys →
{option-ext, redox_users}` compiles on none of our targets. Cargo's resolver
unions target-specific deps into the lockfile without composing nested cfgs, so
it records them anyway. Verified — `cargo tree -i dirs --target <T>` is **empty**
for `x86_64-pc-windows-msvc`, `aarch64-apple-darwin`, `x86_64-apple-darwin`, and
`x86_64-unknown-linux-gnu`; `dirs` appears only under `--target all`.

## License impact and resolution (Option A — owner-approved 2026-07-23)

Under the real `deny.toml`, `cargo-deny check licenses` fails on exactly one
crate: `option-ext` 0.2.0 (MPL-2.0), not on the allowlist. (All other new
crates are MIT/Apache; the Zlib/BSL-1.0/OFL/Ubuntu-font licenses already on the
allowlist are from the M2 eframe tree, not tray.)

Resolution: a per-crate `deny.toml` exception —
`exceptions = [{ name = "option-ext", allow = ["MPL-2.0"] }]` — with the full
phantom justification recorded in `deny.toml`. This keeps all-target cargo-deny
coverage (so Linux advisories, including the tracked wayland-scanner items, stay
scanned) and blesses only this one never-shipped crate; global copyleft stays
disallowed. Measured result with the exception: `advisories ok, bans ok,
licenses ok, sources ok`. The rejected alternative (restricting `[graph].targets`
to Windows/macOS) would pass but drop Linux from cargo-deny's scan entirely — a
real coverage loss — so it was not chosen.

## The decision that keeps the shipped tree clean: NO Linux tray in v1

tray-icon's Linux backend requires the `gtk` feature → gtk-rs 0.18 bindings +
libappindicator. The gtk3 bindings are officially unmaintained (gtk-rs moved to
gtk4). With `default-features = false`, zero gtk/appindicator/xdo crates appear
on the Linux target. So:

- Windows (primary) + macOS: tray compiled in, via target-specific dependency
  declarations in `usage-ui/Cargo.toml`.
- Linux: window-only in v1; tray code cfg'd out entirely. Future option if
  demand appears: `ksni` (pure-Rust D-Bus StatusNotifier, no gtk) as a separate
  reviewed addition — likely M5/M6. (Note: a real Linux tray via any backend
  would make `dirs`/`option-ext` ship, so the MPL-2.0 exception above must be
  revisited at that point.)

macOS cost note: tray-icon pulls objc2 0.6 alongside winit's objc2 0.5 on that
target. Duplicate-version = existing deny.toml "warn"; acceptable for a
best-effort platform. We avoid any png decode path by generating the icon RGBA
at runtime (see plan).

## Trust-boundary statement (unchanged)

`tray-icon` lands in `usage-ui` only. `usage-core` — the trust boundary — gains
nothing: no new crates, no new code paths. The tray receives only the same
non-secret `ProviderSnapshot` data the window already renders. THREAT_MODEL §11
re-check (dependency with serialization/network capability): none of the nine
crates has network capability; `dirs`/`dirs-sys` are filesystem-path helpers but
are phantom (never compiled) and in any case would only resolve OS config dirs,
never touched by our code; the serialization surface is keyboard-types' serde
impls on non-secret key types — §6/§9 rows unchanged, **no THREAT_MODEL.md edit
required**. deny.toml change is the single narrow license exception above.

## M3.5 scope (owner plan-approved 2026-07-20; unchanged by this correction)

Phase A (top-tier bytes, landed via §4a verify-and-commit): the target-gated
`tray-icon` dependency in `usage-ui/Cargo.toml`, the CONTRIBUTING.md row, and
the `deny.toml` exception. Phase B (Sonnet, usage-ui only): runtime-generated
RGBA icon (no asset file, no build script, no png decode path), live tooltip,
left-click show/raise, Show/Hide/Quit menu, close-to-tray default with a
`--no-tray` flag, unit tests for every pure helper. Acceptance: owner's eyes
only. Deferred: dynamic percentage-colored icon states (M5), Linux tray (ksni,
future review), notifications.
