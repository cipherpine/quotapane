## 2. Root cause — the 4 extra crates are PHANTOM (unreachable on every supported target)

`tray-icon 0.24.1`'s own manifest declares `dirs` under:

```toml
[target.'cfg(any(target_os = "linux", target_os = "dragonfly", target_os = "freebsd", target_os = "netbsd", target_os = "openbsd"))'.dependencies.dirs]
version = "6"
```

Our `usage-ui/Cargo.toml` gates tray-icon to `cfg(any(target_os = "windows",
target_os = "macos"))`. **The intersection of {windows, macos} and
{linux, *bsd} is empty**, so the chain `tray-icon → dirs → dirs-sys →
{option-ext, redox_users}` can never compile on any platform we ship. Cargo's
resolver unions target-deps into the lockfile without composing nested cfgs, so
it records these phantom entries anyway.

**Proven** — `dirs` is reachable on 0 of our 4 supported targets:

```
cargo tree -i dirs --target x86_64-pc-windows-msvc   -> (empty)
cargo tree -i dirs --target aarch64-apple-darwin     -> (empty)
cargo tree -i dirs --target x86_64-apple-darwin      -> (empty)
cargo tree -i dirs --target x86_64-unknown-linux-gnu -> (empty)
```

(`dirs` only appears under `cargo tree -i dirs --target all`, i.e. purely as a
lockfile artifact: `dirs ← tray-icon ← usage-ui`.)

## 4. Fix options — tested in scratch copies (repo `deny.toml` never touched)

cargo-deny `check licenses` behavior mapped by `[graph].targets`:

| `targets` | licenses result |
|---|---|
| `["x86_64-pc-windows-msvc"]` | ✅ ok |
| `["aarch64-apple-darwin"]` | ✅ ok |
| `["x86_64-apple-darwin"]` | ✅ ok |
| `["x86_64-unknown-linux-gnu"]` | ✅ ok |
| Windows + both macOS (no Linux) | ✅ ok |
| all four (incl. Linux) | ❌ FAILED |

The all-four failure is a cargo-deny **union artifact**: with Linux in the list,
`dirs`'s Linux/BSD cfg is satisfied *and* `tray-icon` is kept via Windows/macOS,
so `dirs`→`option-ext` is pulled in even though no single target makes the whole
path live.

### Option A (RECOMMENDED) — per-crate license exception, keeps all-target coverage
Add to `[licenses]` in `deny.toml`:

```toml
exceptions = [
    # option-ext (MPL-2.0) is a transitive dep of `dirs`, which tray-icon only
    # uses on Linux/BSD. We gate tray-icon to Windows/macOS, so this chain is
    # UNREACHABLE on every target we build (verified: `cargo tree -i dirs
    # --target <each>` is empty). option-ext is never compiled, linked, or
    # distributed, so MPL-2.0's file-level copyleft never attaches. Allowed for
    # this one crate only; global copyleft stays disallowed.
    { name = "option-ext", allow = ["MPL-2.0"] },
]
```

**Proven result:** `advisories ok, bans ok, licenses ok, sources ok` (full
`cargo deny check`, all targets, repo config + this exception).
Trade-off: none for coverage — cargo-deny still scans all targets. Cost: one
"blessed" copyleft crate that never ships (documented above).

### Option B — restrict `[graph].targets` to the shipped set (no Linux)
Set `targets = ["x86_64-pc-windows-msvc", "aarch64-apple-darwin",
"x86_64-apple-darwin"]`. **Proven** to pass. Trade-off: cargo-deny no longer
scans the Linux build for *any* check (advisories/bans/licenses/sources), a real
supply-chain coverage reduction on the best-effort Linux target. Weaker than A.

### Option C — drop `dirs` upstream
Not feasible without patching tray-icon: `dirs` is tray-icon's own target dep,
not something a feature flag toggles. `[patch]`-ing a third-party crate is a
larger surface than A. Not recommended.
